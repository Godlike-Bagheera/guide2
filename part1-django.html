Часть 1. Бэкенд на Django

1. Введение в бэкенд

Мы создадим REST API для управления заметками. Каждая заметка имеет:

  • ID — автоматический идентификатор (создаёт Django)
  • title — короткий заголовок (до 200 символов)
  • content — текст заметки (без ограничения)
  • created_at — дата создания (проставляется автоматически)
  • owner — ссылка на пользователя-создателя

API будет поддерживать 5 операций — классический CRUD:

CRUD-операции API заметок
ОперацияМетод HTTPURLЧто делает
CreatePOST/api/notes/Создать заметку
Read (list)GET/api/notes/Список всех заметок
Read (one)GET/api/notes/1/Одна заметка по ID
UpdatePUT/PATCH/api/notes/1/Обновить заметку
DeleteDELETE/api/notes/1/Удалить заметку

2. Почему без sudo и как это работает

В РЕД ОС команда dnf install требует прав суперпользователя — при попытке запуска без sudo вы получите ошибку: «Эту команду нужно запускать с привилегиями суперпользователя». Поэтому мы не будем использовать системный менеджер пакетов вообще.

Наш подход:

КомпонентКак ставимГде живёт
Python и зависимостиvenv~/projects/fullstack-app/venv/
Node.js и npmnvm~/.nvm/
Django-проектdjango-admin~/projects/fullstack-app/backend/
React-проектvite~/projects/fullstack-app/frontend/

Бонус: изолированное окружение — вы не сломаете систему и не получите конфликтов версий с уже установленными пакетами.

Откройте терминал (в РЕД ОС это обычно GNOME Terminal) и выполните:

РЕД ОС обычно поставляется с Python 3.10 или 3.11. Если ничего не работает — попросите администратора установить только Python, остальное мы сделаем сами.

3.2. Создайте папку проекта

3.3. Создайте виртуальное окружение

Что такое venv? Это изолированная среда Python. Всё, что вы установите внутри неё (через pip), будет лежать в папке venv/ и не затронет системный Python. Никакого sudo не нужно.

Вы увидите, что приглашение терминала изменилось — появился префикс (venv):

Совет: Чтобы выйти из окружения, введите deactivate. Чтобы вернуться — source venv/bin/activate из папки проекта.

Что такое JWT? JSON Web Token — стандарт передачи данных между сторонами в виде JSON-объекта. Сервер выдаёт клиенту access token (короткоживущий) и refresh token (долгоживущий). Клиент прикладывает access token к каждому запросу в заголовке Authorization: Bearer <token>. Когда access истекает — использует refresh. Разбор на jwt.io.

5. Django Admin — готовая админка из коробки

Одна из главных «киллер-фич» Django: панель администратора создаётся автоматически из ваших моделей. Не нужно писать HTML, forms и CRUD-логику — Django сгенерирует интерфейс для добавления, редактирования и удаления записей. Идеально, чтобы быстро наполнять базу данными и смотреть, как работают модели.

5.1. Включён ли Admin?

В свежем проекте всё уже включено по умолчанию. Проверьте два файла:

# backend/settings.py
INSTALLED_APPS = [
    ...
    'django.contrib.admin',       # ← сама админка
    'django.contrib.auth',        # ← пользователи и права
    ...
]

MIDDLEWARE = [
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.contrib.auth.middleware.AuthenticationMiddleware',  # ← без него admin не пустит
    ...
]python

Как это работает: админка построена на тех же моделях, что и ваш сайт. Таблица в браузере — это буквально Model.objects.all(), а форма редактирования автоматически строится из полей модели (CharField → текстовое поле, DateTimeField → виджет с календарём и т.д.).

5.2. Создайте суперпользователя

В админку может зайти только staff-пользователь. Создаём его одной командой:

python manage.py createsuperuserbash

Django спросит имя, email и пароль (минимум 8 символов, пароль нельзя использовать как логин). Если модель ещё не создана — сначала выполните makemigrations и migrate.

5.3. Вход в админку

# запустите сервер
python manage.py runserverbash

Откройте в браузере: http://127.0.0.1:8000/admin/ — увидите форму входа. URL задаётся в backend/urls.py:

# backend/urls.py
from django.contrib import admin
from django.urls import path

urlpatterns = [
    path('admin/', admin.site.urls),   # ← вся админка живёт здесь
    path('api/', include('api.urls')),
]python

5.4. Зарегистрируйте модель

По умолчанию в админке видны только Группы и Пользователи. Чтобы появились ваши заметки, зарегистрируйте модель в api/admin.py:

# api/admin.py
from django.contrib import admin
from .models import Note


@admin.register(Note)
class NoteAdmin(admin.ModelAdmin):
    list_display = ('id', 'title', 'owner', 'created_at')  # колонки списка
    list_filter = ('created_at', 'owner')                  # фильтры сбоку
    search_fields = ('title', 'content')                   # строка поиска
    ordering = ('-created_at',)                            # сортировка по умолчанию
    readonly_fields = ('created_at',)                      # только для чтенияpython

Старый стиль регистрации — admin.site.register(Note) — тоже работает, но класс с настройками удобнее. После сохранения страницы обновите админку: в разделе «Api» появится «Заметки» со списком, поиском и кнопкой «Добавить».

5.5. Что умеет админка

ФункцияКак выглядитНастройка

Inline-редактированиедочерние записи прямо в форме родителяadmin.StackedInline

Пример inline — теги заметки редактируются в её же форме:

class NoteTagInline(admin.TabularInline):
    model = Note.tags.through   # промежуточная таблица ManyToMany
    extra = 1                    # одна пустая строка для нового тега


@admin.register(Note)
class NoteAdmin(admin.ModelAdmin):
    inlines = [NoteTagInline]python

Не выставляйте /admin/ в интернет без настройки! Смените путь path('admin/', ...) на нестандартный, включите DEBUG=False, держите сильный пароль и выдавайте staff-права только нужным группам. Админка — самый лакомый объект для брутфорса.

Итого: createsuperuser → заход на /admin/ → регистрация модели через @admin.register — и у вас полноценная CMS для проекта за 5 минут. На этом этапе можно руками добавить тестовые заметки и проверить API-эндпоинты на реальных данных.

6. Django + Bootstrap 5 — django_bootstrap5

Пока React — это про API и SPA, многие задачи решаются проще: обычные страницы рендерит сам Django через шаблоны. Чтобы сайт выглядел красиво, используем Bootstrap 5 — самый популярный CSS-фреймворк, а для интеграции с Django — пакет django_bootstrap5.

6.1. Установка django_bootstrap5

Убедитесь, что окружение (venv) активно (раздел 3), и выполните:

pip install django-bootstrap5bash

Не путайте имена! В pip install пакет пишется django-bootstrap5 (через дефис), а в settings.py — django_bootstrap5 (через подчёркивание). Это одно и то же.

Затем откройте backend/backend/settings.py и добавьте приложение в INSTALLED_APPS:

INSTALLED_APPS = [
    'django.contrib.admin',

    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    # Сторонние
    'rest_framework',
    'django_bootstrap5',   # ← Bootstrap 5 для Django
    # Наше

]python

Настройки самого bootstrap-пакета можно добавить в конец того же файла (не обязательно, по умолчанию всё уже хорошо):

# settings.py — опционально

6.4. Сайт как конструктор: берём готовые куски кода с сайта Bootstrap

Главная фишка Bootstrap — готовые компоненты: навбары, карточки, формы входа, футеры, hero-блоки. Их не нужно писать руками — их можно копировать прямо с официального сайта и вставлять в наши шаблоны Django. django_bootstrap5 уже подключил нужные CSS и JS, поэтому скопированный HTML заработает «из коробки» — это и есть сборка сайта как из кубиков LEGO.

Где брать готовые куски кода:

  • getbootstrap.com/docs/5.3/components — официальные примеры компонентов (Navbar, Cards, Buttons, Forms, Modals…) — жмите «Copy» на любом примере
  • getbootstrap.com/docs/5.3/examples — готовые целые страницы: блоги, лендинги, панели администратора — можно забирать целиком
  • Сетка (Grid) — база основ: container → row → col-*
  • MDBootstrap (MDB) — сотни бесплатных расширенных примеров на Bootstrap 5
  • Bootswatch — готовые цветовые темы для Bootstrap

Как перенести пример в Django-шаблон — три шага:

  1. Открыли страницу компонентов Bootstrap, выбрали нужный блок (например, Navbar), нажали Copy
  2. Вставили HTML внутрь {% block content %}...{% endblock %} нашего шаблона
  3. Заменили «статичный» текст на переменные Django — {{ note.title }}, циклы {% for %}, ссылки {% url %}

Пример: скопированный с сайта Bootstrap навбар превращаем в живой навбар Django:

<!-- скопировано с getbootstrap.com/docs/5.3/components/navbar -->
<nav class="navbar navbar-expand-lg navbar-dark bg-dark">
  <div class="container-fluid">
    <a class="navbar-brand" href="{% url 'home' %}">Мои заметки</a>
    <button class="navbar-toggler" type="button" data-bs-toggle="collapse"
            data-bs-target="#menu">
      <span class="navbar-toggler-icon"></span>
    </button>
    <div class="collapse navbar-collapse" id="menu">
      <ul class="navbar-nav me-auto">
        <li class="nav-item"><a class="nav-link" href="{% url 'home' %}">Главная</a></li>
        <li class="nav-item"><a class="nav-link" href="/admin/">Админка</a></li>
      </ul>
    </div>
  </div>
</nav>html

А карусель или сетку карточек из примеров сайта — в вывод данных из базы:

<div class="row">
  {% for note in notes %}
    <div class="col-md-4 mb-4">
      <div class="card shadow-sm h-100">
        <div class="card-body">
          <h5 class="card-title">{{ note.title }}</h5>
          <p class="card-text">{{ note.content|truncatewords:20 }}</p>
        </div>
        <div class="card-footer bg-transparent border-0 pb-3">
          <a href="#" class="btn btn-sm btn-outline-primary">Открыть</a>
        </div>
      </div>
    </div>
  {% endfor %}
</div>html

Два нюанса при копировании:
• Не копируйте теги <link>/<script> с CDN из примеров Bootstrap — у нас за это отвечают {% bootstrap_css %} и {% bootstrap_javascript %}, иначе стили загрузятся дважды.
• Interactivity (бургер-меню, модалки) работает через атрибуты data-bs-* — их менять не надо, достаточно {% bootstrap_javascript %} в базовом шаблоне.

Итог раздела: сайт действительно собирается как конструктор — открываете сайт Bootstrap, копируете приглянувшийся блок, вставляете в шаблон, подменяете текст на {{ переменные }} Django. Красивая вёрстка без единой строчки собственного CSS.

7. Модель, сериализатор, представления

7.1. Модель api/models.py

Модель — это Python-класс, который описывает таблицу в БД. Django сам создаёт SQL-таблицу на основе класса.

from django.db import models


class Note(models.Model):
    """Заметка пользователя."""
    title = models.CharField(
        max_length=200,
        verbose_name='Заголовок',
    )
    content = models.TextField(
        verbose_name='Содержание',
    )
    created_at = models.DateTimeField(
        auto_now_add=True,
        verbose_name='Создано',
    )
    owner = models.ForeignKey(
        'auth.User',
        on_delete=models.CASCADE,
        related_name='notes',
        verbose_name='Владелец',
    )

    class Meta:
        verbose_name = 'Заметка'
        verbose_name_plural = 'Заметки'
        ordering = ['-created_at']

    def __str__(self):
        return self.titlepython

ForeignKey создаёт связь «многие к одному» — у одного пользователя много заметок. on_delete=CASCADE означает: при удалении пользователя удалятся его заметки. related_name='notes' позволяет обращаться к заметкам как user.notes.all().

7.2. Сериализатор api/serializers.py

Создайте файл api/serializers.py. Сериализатор конвертирует объекты Python ↔ JSON.

from rest_framework import serializers
from .models import Note


class NoteSerializer(serializers.ModelSerializer):
    owner = serializers.ReadOnlyField(source='owner.username')

    class Meta:
        model = Note
        fields = ['id', 'title', 'content', 'created_at', 'owner']
        read_only_fields = ['id', 'created_at', 'owner']python

ReadOnlyField для owner означает: клиент не может подделать владельца — он всегда берётся из request.user на сервере.

7.3. Представления api/views.py

from rest_framework import generics, permissions
from .models import Note
from .serializers import NoteSerializer


class NoteListCreateView(generics.ListCreateAPIView):
    """GET /api/notes/  — список; POST /api/notes/ — создание."""
    serializer_class = NoteSerializer
    permission_classes = [permissions.IsAuthenticatedOrReadOnly]

    def get_queryset(self):
        return Note.objects.all().order_by('-created_at')

    def perform_create(self, serializer):
        # Владелец всегда текущий пользователь — подделать нельзя
        serializer.save(owner=self.request.user)


class NoteDetailView(generics.RetrieveUpdateDestroyAPIView):
    """GET/PUT/PATCH/DELETE /api/notes/:id/."""
    queryset = Note.objects.all()
    serializer_class = NoteSerializer
    permission_classes = [permissions.IsAuthenticatedOrReadOnly]python

9. JSONPlaceholder

JSONPlaceholder (jsonplaceholder.typicode.com) — бесплатный фейковый REST API для тестирования и прототипирования. Не требует регистрации и API-ключей.

9.1. Основные эндпоинты

# Список постов (100 штук)
curl https://jsonplaceholder.typicode.com/posts

# Один пост
curl https://jsonplaceholder.typicode.com/posts/1

# Комментарии к посту
curl https://jsonplaceholder.typicode.com/posts/1/comments

# Пользователи
curl https://jsonplaceholder.typicode.com/users

# Пагинация через query-параметры
curl "https://jsonplaceholder.typicode.com/posts?_limit=5&_page=2"bash

9.2. Таблица возможностей

МетодURLЧто делаетСохраняет?
GET/postsСписок постов—
GET/posts/1Один пост—
GET/posts/1/commentsКомментарии поста—
GET/usersСписок пользователей—
POST/postsСоздать пост❌ фейк
PUT/posts/1Обновить❌ фейк

9.3. Пример POST-запроса

curl -X POST https://jsonplaceholder.typicode.com/posts \
  -H "Content-Type: application/json" \
  -d '{"title": "Тест", "body": "Содержимое", "userId": 1}'

# Ответ (сервер вернёт «успех», но не сохранит):
# {"id": 101, "title": "Тест", "body": "Содержимое", "userId": 1}bash

Зачем это вам? Пока разрабатываете фронтенд, бэкенд может быть не готов. JSONPlaceholder даёт «заглушку», чтобы верстка и логика фронтенда работали уже сейчас.

Важно: JSONPlaceholder не сохраняет изменения. POST/PUT/DELETE возвращают «успешный» ответ, но данные на сервере не меняются. Это чисто учебный/тестовый инструмент.

10. Углубляемся: что такое DRF под капотом

Разберёмся, что именно делают generics.ListCreateAPIView и ModelSerializer — вы будете видеть их постоянно.

10.1. Что делает ListCreateAPIView

Он объединяет два класса: ListModelMixin (GET-список) и CreateModelMixin (POST). Когда приходит запрос:

  1. Срабатывает get_queryset() — возвращает объекты из БД
  2. serializer_class конвертирует их в JSON
  3. permission_classes проверяет права
  4. Для POST вызывается perform_create() — там мы задаём owner

10.2. Что делает ModelSerializer

Он автоматически:

  • Читает поля из модели (title, content, created_at...)
  • Создаёт валидаторы (CharField → max_length=200)
  • Реализует create() и update()
  • Валидирует данные по типам

Ручной сериализатор для той же модели выглядел бы так (для сравнения):

class NoteSerializer(serializers.Serializer):
    id = serializers.IntegerField(read_only=True)
    title = serializers.CharField(max_length=200)
    content = serializers.CharField()
    created_at = serializers.DateTimeField(read_only=True)
    owner = serializers.CharField(source='owner.username', read_only=True)

    def create(self, validated_data):
        return Note.objects.create(**validated_data)

    def update(self, instance, validated_data):
        instance.title = validated_data.get('title', instance.title)
        instance.content = validated_data.get('content', instance.content)
        instance.save()
        return instancepython

ModelSerializer делает то же самое за 5 строк вместо 15 — и это только для одной модели.
